# STM32F446RE Learning Projects

My first steps with the **NUCLEO-F446RE** board (STM32F446RE, ARM Cortex-M4), going from the HAL library down to direct register access. Each folder is a separate STM32CubeIDE project.

| Project | Level | What it does |
|---|---|---|
| [`Nucleo_F446_First_Project`](Nucleo_F446_First_Project) | HAL | Blinks the on-board LED (LD2, PA5) every 500 ms and prints a counter with `printf`, redirected to the debugger's SWV/ITM console (`_write` → `ITM_SendChar`). |
| [`F446_BareMetal`](F446_BareMetal) | Registers | Configures clocks, GPIO, EXTI and USART2 directly through registers. Pressing the blue user button (PC13) fires an EXTI interrupt that toggles the LED. Prints a greeting over USART2 using a small driver written from scratch (`usart2.c`, with a `printf`-style `printUSART`). |
| [`embedded-journey`](embedded-journey) | Registers | Enables the FPU and runs a small interactive shell over USART2: type `On`, `Off` or `Blink` in a serial terminal to control the LED. In blink mode, any key returns to the menu. Extends the USART2 driver with receive functions (`USART2_read`, `USART2_readString`). |

## Hardware

- NUCLEO-F446RE board, connected over USB (ST-LINK).
- USART2 (PA2 = TX, PA3 = RX) is routed to the ST-LINK virtual COM port, so no extra wiring is needed.
- Serial terminal settings for the register-level projects: **9600 baud, 8N1** (e.g. PuTTY, Tera Term or the STM32CubeIDE terminal).

## Opening a project

1. In STM32CubeIDE: **File → Import → General → Existing Projects into Workspace**, and select the project folder.
2. **Restore the ST driver files:** the `Drivers/` folder (CMSIS and the STM32F4 HAL, generated by ST) is not stored in this repository. Open the project's `.ioc` file and click **Project → Generate Code**. Code written between the `USER CODE BEGIN` / `USER CODE END` markers is kept.
3. Build (hammer icon) and run/debug on the board.

For `Nucleo_F446_First_Project`, the `printf` output appears in the **SWV ITM Data Console** while debugging (enable SWV in the debug configuration, with the core clock set to the project's clock).

## Repository layout

Each project contains:

- `Core/Src`, `Core/Inc` — application code (`main.c`, the USART2 driver) and the files CubeIDE generated for it
- `Core/Startup` — startup file and vector table
- `*.ioc` — CubeMX configuration (pins and clocks)
- `STM32F446RETX_FLASH.ld`, `STM32F446RETX_RAM.ld` — linker scripts
- `.project`, `.cproject`, `.mxproject` — STM32CubeIDE project files

Build output (`Debug/`, `Release/`), the generated `Drivers/` folder and machine-specific IDE files are excluded by `.gitignore`.
